英語の教材を読み込むと、含まれている単語と熟語を自動で抽出して、自分専用の単語帳にしてくれるWebアプリを作りました。

**[Glossalyze（グロサライズ）](https://glossalyze.sawa0911a.workers.dev/)**

ブラウザだけで動きます。インストール不要、無料です。

![教材の上で単語をタップすると語義が出る。右側に語彙カバレッジと未知語の一覧](/images/material-detail.png)
*教材を読み込むと、語をタップして意味を確認しながら、その場で単語帳に追加できる*


## 作った動機

英語の勉強では、問題を解きながら、その中の分からない単語を単語帳に追加して覚えていく、という進め方をよくします。英語の問題集や論文を読んでいると、知らない単語をその都度調べて、単語帳に登録する必要があります。

一方で、市販の単語帳は収録語があらかじめ決まっています。

たとえば『TOEIC L & R TEST 出る単特急 金のフレーズ』（TEX加藤, 2017, 朝日新聞出版）は、TOEICで頻出する単語をまとめたものです。よくできた本ですが、収録語は固定です。そしてTOEIC自体の難易度や出題傾向は年々変化します。

さらに言えば、あらかじめ決められた単語集は、**利用者が実際に読んでいる教材にも、その人の既知語・未知語にも必ずしも一致しません**。すでに知っている語を覚え直すことにも、教材に出てこない語に時間を使うことにもなります。

自分が使っている教材と、自分の英語レベルに合った単語帳を簡単に作りたい。それがこのアプリの出発点です。

## 使い方

### 1. 語彙レベルを設定する

初回に自分の語彙レベルを選びます。選んだレベル以下のCEFR-Jの語が、学習済みとしてバックグラウンドで一括登録され、以降の未知語判定の基準になります。

### 2. 教材を読み込む

英語のPDFを選ぶか、プリントをカメラで撮影します。iOSではVisionKit、AndroidではML Kitで輪郭を検出し、自動で補正・トリミングします。複数ページを続けて撮ってひとつの教材にまとめられます。

![PDFに名前を付けて読み込み、解析が終わって教材が開くまで](/images/import.gif)
*PDFを選んで名前を付けると、解析が終わり次第そのまま開く*

![スマートフォンのカメラで本のページをスキャンしている様子](/images/scan.gif)
*書類スキャンは輪郭を自動検出する。複数ページを続けて撮れる*


Web版は画像またはPDFのアップロードです。

- 画像: JPEG / PNG / WebP / GIF、最大10MB
- PDF: 最大50MB、プレビューとOCRは50ページまで

![スマートフォンで紙のプリントを撮影して読み込んだ画面](/images/mobile-scan.png)
*書き込みのある紙のプリントでも読み込める。下部には検出された熟語が並ぶ*


### 3. 抽出された語彙を確認して単語帳に入れる

読み込みが終わると、教材に含まれる単語と熟語の一覧が出ます。各語彙は4つに分類されます。

| 分類 | 意味 |
|---|---|
| 全体 | 教材から抽出された語彙すべて |
| 既知 | 学習済みとして登録されている語 |
| 未知 | まだ学習していない語 |
| 訳なし | 語義を取得できなかった語 |

「未知」を見れば、その教材を読むために足りない語彙が分かります。覚えたいものは単語帳へ入れます。

![教材一覧。各教材に習得語彙率と未知語数が表示されている](/images/materials.png)
*読み込んだ教材には、習得語彙率と未知語数が表示される*


## 未知語の判定と語彙カバレッジ

学習済みとして登録されていない単語を「未知語」としています。初期値はレベル設定時にCEFR-Jのワードリストから一括登録され、あとは学習が進むにつれて増えていきます。

![教材の未知語をまとめて新しい単語帳に登録している様子](/images/bulk-register.gif)
*未知語だけを絞り込んで、新しい単語帳にまとめて登録できる*


教材に含まれる語彙が、学習済みの語でどれだけ網羅されているか。これを見れば **自分の語彙とその教材のレベルの差** が分かります。読み始める前に、その教材が今の自分に対して簡単すぎないか、難しすぎないかを判断できます。

![本文を範囲選択して複数の単語の意味をまとめて確認している画面](/images/range-select.png)
*範囲を選択すれば、その中の語をまとめて確認できる*


## 語義は単語と熟語で別系統

**単語**は、CEFR-Jのワードリストに含まれていればその日本語語義・IPA・例文を使います。含まれない語は、Wiktionary（wiktextract）から英語語義を取得し、それをもとにGemini APIで日本語語義を生成します。

**熟語**は、PHaVE List（句動詞）やPHRASE List（英熟語）といったリストが日本語語義・例文・訳文を持っているため、そちらを使います。

CEFR-Jと熟語リストのデータは、あらかじめSupabaseの`meanings`テーブルに投入してあります。

単語ごとに、どの出典から来た語義かを表示します。

![本文中の語をクリックして語義を表示している様子](/images/word-popup.gif)
*熟語も本文中でそのまま確認できる*

![単語帳。各語に出典（Wiktionary / Phrase List / CEFR-J）が表示されている](/images/wordbook.png)
*語ごとに出典が表示される。熟語には「熟語」タグが付く*


## その他の機能

### 出現回数で絞り込む

単語帳の語について、集計対象の教材を選ぶと、その教材群の中で各語が何回出現したかが表示されます。最低出現回数を指定すれば、よく出てくる語だけに絞り込めます。

![集計対象の教材を選んで、出現回数で単語を絞り込んでいる様子](/images/frequency.gif)


### 3種類の学習モード

- **フラッシュカード** — カードをめくって確認
- **4択問題** — 選択式
- **テスト** — 結果画面で間違えた語をまとめて確認でき、正解した語をそのまま学習済みにできる

![フラッシュカードで単語を確認している様子](/images/flashcard.gif)


単語帳直下の語だけでも、配下のフォルダをまとめてでも学習できます。

![単語帳フォルダの画面。「フォルダ内をまとめて学習」ボタンがある](/images/wordbook-folder.png)


### 発音

IPAを表示します。Web版はブラウザの音声合成で読み上げます。

### ダッシュボード

習得語彙数、登録語彙数、習得語彙率、直近に読み込んだ教材が並びます。

## 技術構成

![技術スタック図。利用者・フロントエンド・バックエンド・外部サービスの4層構成](/images/tech-stack.png)


### フロントエンド

| 技術 | 用途 |
|---|---|
| Flutter / Dart | Web・iOS・Android の共通実装 |
| Riverpod | 状態管理 |
| GoRouter | ルーティング |
| Supabase Auth | メール認証・Google OAuth |
| Cloudflare Workers | ホスティング（Static Assets） |

画面幅に応じてPC向けとスマートフォン向けのレイアウトを切り替えています。

### バックエンド

| 技術 | 用途 |
|---|---|
| FastAPI | API |
| Supabase (PostgreSQL) | ユーザー情報・単語帳データ・語義データ |
| Oracle Object Storage (S3互換) | 教材原本・PDF・サムネイル・OCR位置情報 |
| Azure Document Intelligence | 主OCR |
| Tesseract | OCRフォールバック |
| Poppler | PDFの画像化 |
| spaCy (`en_core_web_sm`) | 形態素解析・依存関係解析 |
| Wiktionary / wiktextract | 英語語義 |
| Gemini API | 英語語義をもとにした日本語語義の生成 |

### OCRの処理順

画像とPDFはどちらも次の順で処理します。

1. Azure Document Intelligence
2. Azureが未設定・制限超過・失敗のいずれかならTesseract

PDFはPopplerの`pdftoppm`でページ画像を生成します。抽出可能なテキストレイヤーがある場合はそれもフォールバックとして使用し、問題のあるPDFはGhostscriptがあれば修復を試みます。

OCR結果と位置情報は教材登録時に保存され、教材表示のたびに再OCRは行いません。

## 今後

### サーバの性能とコスト

現在サーバは無料枠で動かしていて、性能が足りていません。形態素解析と依存関係解析を行っているspaCyの処理を、API化するなどしてサーバの外へ逃がしたいと考えています。

あわせて、文字数が膨大な教材を読み込んだときの動作も、もっと軽くしたいところです。

### 英日辞書データの組み込み

CEFR-Jや熟語リストに無い単語の日本語語義は、現在Gemini APIで生成しています。使用制限と生成される語義の精度に不安が残るため、Collinsなどの英日辞書のデータを組み込みたいと考えています。

### 試験別の単語帳

「金フレ」は、TOEICの出題傾向を分析してまとめられた単語帳です。

利用者が増えれば、TOEICなどの試験に頻出する語のデータがアプリ側に集まります。これをもとに、同じように出題傾向を分析した単語帳を、**年度を指定できる形で**、しかもTOEICに限らず幅広い試験について、アプリ利用者全体に提供できると考えています。

### 初期学習済み単語の最適化

学習開始時の初期学習済み単語は、現在CEFR-Jのリストで決めています。ここもユーザーの利用データが集まれば、より最適化できるはずです。

### 問題演習と、語彙レベルと正解率の関係

Azure Document Intelligenceは、文書内の構成要素を分析できます。「ここは問題文」「ここは選択肢」といった構造を読み取れるということです。

これを使って問題文と選択肢を問題ごとに切り分ければ、UI上で回答できるようになります。答えのデータもあれば、答え合わせと正答率のデータまで扱えます。

そこまで来ると、**自分と教材の語彙レベルの差分と、正解率の関係**を分析対象にできると考えています。

## まとめ

読んでいる教材そのものから単語帳を作る、というのがコンセプトです。市販の単語帳と違って、覚えた語は必ず目の前の教材に出てきます。

手元にPDFやプリントがあれば1ファイルから試せます。
